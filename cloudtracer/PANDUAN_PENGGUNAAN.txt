================================================================================
  APA ITU CLOUDTRACER?
================================================================================

CloudTracer adalah tool keamanan cloud (cloud security tool) yang digunakan
untuk memvisualisasikan jalur serangan (attack path) pada environment AWS IAM
(Identity and Access Management).

Secara sederhana, CloudTracer menjawab pertanyaan:
  "Apakah user/role ini bisa mendapatkan hak Administrator
   melalui jalur yang tidak langsung?"

Ini sangat berguna untuk:
  - Cloud Security Audit          → audit konfigurasi IAM sebelum production
  - Red Team IAM Assessment       → simulasi jalur eskalasi privilege
  - Threat Modeling               → pemetaan risiko permission AWS
  - Edukasi AWS Security          → belajar memahami model permission AWS

================================================================================
  FUNGSI UTAMA TOOL INI
================================================================================

1. PARSE IAM DATA
   Membaca file JSON yang berisi konfigurasi seluruh IAM sebuah akun AWS,
   mencakup: Users, Groups, Roles, dan Policies beserta isi dokumen policy-nya.

2. BUILD ATTACK GRAPH
   Membangun directed graph (graf berarah) yang merepresentasikan hubungan
   antar entitas IAM:
   - Siapa member group mana
   - Policy apa yang melekat ke user/group/role
   - Action berbahaya apa yang diizinkan policy tersebut
   - Role mana yang bisa di-assume oleh siapa

3. FIND ATTACK PATHS
   Mencari semua jalur dari setiap user/role menuju "target berbahaya" seperti:
   - AdministratorAccess
   - iam:PassRole, iam:AttachUserPolicy, iam:CreateUser
   - sts:AssumeRole ke role yang punya akses admin
   Menggunakan algoritma BFS (Breadth-First Search) dengan cutoff 5 hop.

4. RISK SCORING
   Menghitung skor risiko (0-100) untuk setiap entitas berdasarkan:
   - Jarak ke target berbahaya (hop count)
   - Permission berbahaya yang dimiliki
   - Trust policy yang terlalu terbuka

   Label risiko:
   CRITICAL  = skor 80-100  (merah)
   HIGH      = skor 60-79   (oranye)
   MEDIUM    = skor 40-59   (kuning)
   LOW       = skor 0-39    (hijau)

5. VISUALISASI INTERAKTIF
   Menghasilkan file HTML yang bisa dibuka di browser berisi graph interaktif:
   - Klik dan drag node
   - Hover untuk melihat detail permissions
   - Node lebih besar = risiko lebih tinggi
   - Warna node = tingkat risiko

================================================================================
  CARA MENDAPATKAN FILE IAM DUMP
================================================================================

CARA 1 — Dari AWS CLI (akun AWS nyata):
  Pastikan sudah configure AWS credentials:
    aws configure

  Lalu jalankan:
    aws iam get-account-authorization-details --output json > iam_dump.json

  Perintah ini mengambil seluruh konfigurasi IAM akun AWS kamu,
  termasuk semua user, group, role, dan policy beserta isinya.

  PERHATIAN: Perintah ini membutuhkan permission:
    iam:GetAccountAuthorizationDetails
  Biasanya hanya bisa dijalankan oleh akun dengan hak tinggi (admin).

CARA 2 — Dari LocalStack (simulasi AWS di lokal):
  LocalStack adalah tools untuk mensimulasikan AWS secara lokal.
  Setelah LocalStack berjalan:
    aws --endpoint-url=http://localhost:4566 iam get-account-authorization-details > iam_dump.json

CARA 3 — Gunakan sample data yang sudah disertakan:
  File: sample_data/sample_iam_dump.json
  Sudah berisi skenario IAM realistis dengan konfigurasi berbahaya.
  Cocok untuk demo dan latihan tanpa perlu akun AWS.

================================================================================
  MEMAHAMI OUTPUT — ATTACK GRAPH
================================================================================

WARNA NODE:
  Merah terang     → CRITICAL risk (skor 80-100)
  Oranye           → HIGH risk (skor 60-79)
  Kuning           → MEDIUM risk (skor 40-59)
  Hijau            → LOW risk (skor 0-39) untuk user/role
  Biru             → User (default, sebelum scoring)
  Abu-abu          → Policy node
  Merah solid      → Permission berbahaya

UKURAN NODE:
  Semakin BESAR node = semakin TINGGI risk score-nya.
  Formula: ukuran = 15 + (risk_score / 5)

WARNA EDGE (Garis penghubung):
  Ungu             → CanAssume (bisa melakukan AssumeRole)
  Biru             → MemberOf (user adalah anggota group)
  Abu-abu muda     → DirectlyAttached (policy langsung ke user)
  Oranye           → GroupAttached (policy melekat via group)
  Hijau            → RoleAttached (policy melekat ke role)
  Merah            → Allows (policy mengizinkan action berbahaya)

CARA MEMBACA ATTACK PATH:
  Contoh temuan: user:alice → group:developers → policy:DevPolicy → permission:iam:passrole

  Artinya:
  1. alice adalah anggota group "developers"
  2. Group "developers" punya policy "DevPolicy"
  3. DevPolicy mengizinkan action "iam:PassRole"
  4. Dengan iam:PassRole, alice bisa memberikan role ke Lambda/EC2
     yang punya AdministratorAccess → eskalasi privilege!

================================================================================
  MEMAHAMI OUTPUT — FINDINGS.JSON
================================================================================

Setiap temuan dalam findings.json memiliki struktur:

  {
    "source": "user:bob",                    ← Entitas sumber (korban/attacker)
    "target": "permission:iam:passrole",     ← Target berbahaya yang bisa dicapai
    "shortest_path": [                       ← Jalur terpendek ke target
      "user:bob",
      "policy:DevPolicy",
      "permission:iam:passrole"
    ],
    "hop_count": 2,                          ← Jumlah langkah (2 = lebih berbahaya)
    "path_count": 1,                         ← Jumlah jalur alternatif
    "risk_score": 63,                        ← Skor risiko 0-100
    "risk_label": "HIGH",                    ← CRITICAL/HIGH/MEDIUM/LOW
    "reasons": [                             ← Alasan scoring
      "2 hops to dangerous target (+25)",
      "iam:PassRole on * (+20)",
      "iam:AttachUserPolicy (+18)"
    ]
  }

PRIORITAS PENANGANAN:
  1. Perbaiki dulu semua yang CRITICAL (skor 80+)
  2. Lanjut ke HIGH (skor 60-79)
  3. Review MEDIUM sebagai backlog
  4. LOW bisa diterima tapi tetap dicatat

================================================================================
  SKENARIO SAMPLE DATA (sample_iam_dump.json)
================================================================================

Sample data yang disertakan mensimulasikan IAM environment fiktif dengan
konfigurasi berbahaya yang sering ditemukan di real-world audit:

ENTITAS YANG ADA:

  USER: alice
  - Normal user, tidak punya policy langsung
  - Anggota group "developers"
  - RISIKO: Bisa eskalasi privilege via group (3 hop)
  - Score: LOW (15)

  USER: bob
  - Developer, punya DevPolicy langsung (direct attach)
  - DevPolicy mengandung: iam:PassRole + iam:AttachUserPolicy
  - RISIKO TINGGI: 2 hop ke permission berbahaya
  - Score: HIGH (63)

  USER: charlie
  - Tim billing, hanya punya BillingReadOnly
  - Tidak ada permission berbahaya
  - Score: LOW (15)

  GROUP: developers
  - alice dan bob adalah anggotanya
  - Punya DevPolicy (berisi iam:PassRole dan iam:AttachUserPolicy)

  ROLE: admin-role
  - Punya AdministratorAccess (policy AWS managed)
  - Trust policy: hanya akun root yang bisa assume
  - Score: HIGH (75) — sudah punya admin, tapi bukan "bisa dicapai dari luar"

  ROLE: lambda-exec-role
  - Trust policy TERLALU TERBUKA: "Principal": {"AWS": "*"}
  - Siapapun bisa AssumeRole ke role ini!
  - Punya inline policy: iam:PassRole + sts:AssumeRole ke *
  - Score: CRITICAL (92) — kombinasi trust terbuka + dangerous permissions

ATTACK PATH UTAMA yang bisa ditemukan:

  PATH 1 (via bob):
  user:bob → policy:DevPolicy → permission:iam:passrole
  [2 hop, HIGH]
  Bob bisa PassRole ke admin-role karena DevPolicy allow * resource

  PATH 2 (via alice):
  user:alice → group:developers → policy:DevPolicy → permission:iam:passrole
  [3 hop, LOW]
  Alice bisa eskalasi tapi butuh lebih banyak langkah

  PATH 3 (lambda-exec-role):
  role:lambda-exec-role → policy:inline → permission:iam:passrole
  [2 hop, CRITICAL]
  Role ini punya trust terbuka ("*") + langsung bisa PassRole

================================================================================
  TROUBLESHOOTING
================================================================================

MASALAH: "ModuleNotFoundError: No module named 'pyvis'"
SOLUSI:  pip install pyvis

MASALAH: "ModuleNotFoundError: No module named 'fastapi'"
SOLUSI:  pip install fastapi uvicorn[standard] python-multipart

MASALAH: "Address already in use" saat run.py
SOLUSI:  Port 8000 sudah dipakai proses lain. Ubah port di run.py:
         uvicorn.run("app.main:app", port=8001, reload=True)

MASALAH: Graph HTML tidak muncul / blank di browser
SOLUSI:
  - Pastikan file graph.html ada di folder output/{job_id}/
  - Coba buka dengan Chrome (bukan IE/Edge lama)
  - Disable browser extensions yang memblokir JavaScript

MASALAH: "JSON does not appear to be an IAM dump"
SOLUSI:  File JSON yang diupload harus memiliki setidaknya salah satu dari:
         UserDetailList, GroupDetailList, RoleDetailList, Policies
         Periksa apakah file dari perintah yang benar.

MASALAH: "0 attack paths found" padahal ada data
SOLUSI:  Kemungkinan tidak ada policy berbahaya yang dikenali.
         Pastikan policy document berisi action seperti:
         iam:PassRole, iam:AttachUserPolicy, sts:AssumeRole, iam:*, *

MASALAH: "Permission denied" saat jalankan perintah AWS CLI
SOLUSI:  Akun AWS kamu tidak punya iam:GetAccountAuthorizationDetails.
         Minta admin untuk memberikan permission tersebut, atau gunakan
         sample data untuk latihan.
